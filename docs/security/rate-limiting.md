# Límites y abuso

La API y rutas tradicionales de login usan límites configurables por dirección remota y por hash HMAC de cuenta; no se almacena el nombre de cuenta en el cache. Sesión/refresh también tienen límite por dirección; IA, correo y exportaciones tienen ámbitos independientes por usuario. Valores iniciales revisables: `THROTTLE_AUTH=30/min`, `THROTTLE_ACCOUNT=10/min`, y `THROTTLE_EXPENSIVE`, `THROTTLE_EMAIL`, `THROTTLE_EXPORT` a `10/min`. Son valores de arranque, no una estimación de capacidad. Bloqueo por cuenta puede causar denegación dirigida; evaluar políticas de recuperación/alertas.

DRF utiliza cache de Django. El cache local predeterminado es por proceso, no sincroniza workers y las operaciones del throttle no son atómicas bajo concurrencia; no garantiza un límite estricto. `REMOTE_ADDR` evita confiar en encabezados arbitrarios pero puede agrupar usuarios detrás de un proxy. **INFRASTRUCTURE ACTION REQUIRED:** limitar en proxy/WAF, configurar confianza de IP en el borde y, cuando haya varios procesos, valorar almacenamiento compartido con operaciones atómicas. DRF no protege por sí solo contra DDoS ni sustituye límites de tamaño, cuotas y control de concurrencia de IA.
